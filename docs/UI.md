## 원칙
- 규칙을 먼저 정하고 그 안에서 그린다. 그리면서 정하지 않는다
- 껍데기는 공유하고 내용만 갈아끼운다
- 모바일 가로가 기준. PC는 여백이 넉넉해질 뿐이다
- 크기는 항상 Scale(비율). Offset(픽셀 고정)은 쓰지 않는다
- 대량 제작 전에 반드시 관문을 통과한다. 규격 오류는 전량 재작업이다

## 파이프라인

에셋은 피그마에서 만들고, 배치는 전부 코드로 한다.
Studio 안에서 UI를 직접 조립하지 않는다.

```
지환   피그마 → PNG + 배치 명세
희준   로블록스 업로드 → 코드로 배치
지환   Team Create에서 F5로 확인 → 수정 요청 (숫자로)
```

### 역할 경계

| | 지환 | 희준 |
|---|---|---|
| PNG 제작 | O | |
| 3D 파트 (발판·벽·블록·펫) | O | |
| 배치 명세 작성 | O | |
| 로블록스 에셋 업로드 | | O |
| 에셋 ID 관리 | | O |
| 모든 `.lua` | | O |
| Rojo / Git / VS Code | | O |

지환은 피그마와 Studio(Team Create)만 사용한다.

⚠️ 지환 PC의 `C:\privo\privo3-assets`는 PNG 보관용이며 프로젝트가 아니다.
이 폴더에 Rojo를 연결하면 "파일이 정답"이라는 Rojo 구조상
Team Create의 스크립트가 전부 삭제된다.

### 수정 요청은 숫자로

"좀 좁다"는 왕복을 늘린다. `Size {0.22, 0},{0.07, 0}`처럼 값으로 전달한다.
화면이 많아서 왕복 한 번의 비용이 누적된다.

코드 Phase와 독립적으로 진행한다. 지환은 Phase 4~5를 기다리지 않는다.

| U4 | 코어 화면 | 클리어·실패·로딩 + 3D 안내 | | |

### 힘 · 레벨 · 속도 블록 (하단 중앙)

셋을 한 덩어리로 묶는다. 같은 파생 사슬이기 때문이다.

    힘 → 레벨(힘의 지수 기반) → 최대 이동속도(레벨 1당 +1)

떨어뜨려 놓으면 유저가 셋의 관계를 모른다. 붙여두면 힘이 오를 때
레벨과 속도가 같이 오르는 게 한눈에 보인다.

    힘 수치        특대(7%). 8자 기준 (999.99AB)
    레벨 진행 바    다음 레벨까지 채운다. 바 양끝에 현재 / 다음 레벨
    이동 속도      "277 / 최대 277". 연필 아이콘으로 편집. 3~4자리

레벨과 힘은 환생 시 함께 리셋된다.

**진행 바는 다음 레벨까지다. 다음 환생까지가 아니다.**
환생은 유저가 직접 판단해서 누르는 것이지 자동으로 도달하는 지점이
아니다. 환생 시점 판단에 필요한 정보(몇 배수를 얻고 얼마가 버려지는가)는
환생 창에서 보여준다.

#### 이동 속도 조절은 편의 기능이 아니다

수령 발판과 진행 벽이 3D 이동으로 선택되는 구조라, 속도가 수백이면
발판을 밟으려다 벽을 통과해버린다. 런 하나가 통째로 날아간다.
유저가 속도를 낮출 수 있어야 오조작이 막힌다.

그래서 설정 창에 넣지 않고 상시 노출한다. 묻어두면 유저가 런을
여러 번 날린 뒤에야 발견한다.

기본값은 최대다. 저장하지 않고 접속·환생 시 최대로 리셋된다
(→ `DESIGN.md`, `ROADMAP.md` Phase 4-1).

⚠️ 숫자 폭이 재화와 다르다. 속도는 3~4자리이고 재화 8자 규격
   (999.99AB)을 따르지 않는다. 같은 칸으로 묶지 않는다.

### 수령·진행이 UI에 없는 이유

3D 오브젝트로 처리한다. 발판을 밟으면 수령, 벽을 통과하면 진행.
진행이 3D 이동인데 수령만 화면 버튼이면 두 선택이 같은 층위로 느껴지지 않는다.
푸시-유어-럭 구조에서는 "몸으로 선택하는" 감각이 중요하다.

상세는 `DESIGN.md` "1. 챌린지 > 선택 방식" 참조.

### 자동 진행 설정 창

토글이 아니라 창이다. 목표층을 유저가 직접 정하기 때문
(→ `DESIGN.md` "1. 챌린지 > 자동 진행 모드").

    구성   안전층 표시 · 목표층 입력 · 시작 버튼
    미보유 버튼이 잠김 상태(중립 회색). 창은 열리지 않는다

**색이 판단을 대신한다.** 입력한 목표층이 안전층 이하면
수령 · 안전(노랑), 초과하면 진행 · 도박(보라)으로 시작 버튼이 바뀐다.
숫자를 비교하지 않아도 지금 도박을 거는 중인지가 색으로 읽힌다.
발판(노랑)과 벽(보라)이 이미 같은 뜻으로 쓰이므로 학습 비용이 없다.

안전층 초과 입력을 막지 않는다. 막으면 자동 진행이 "절대 실패하지
않는 기능"이 되어 푸시-유어-럭이 성립하지 않는다.

### 환생 창 — 반드시 보여야 하는 것

환생은 블럭스를 전액 소모하고, 1000 단위로만 배수가 붙고 나머지는
버려진다. 1999 블럭스로 환생하면 +1만 얻고 999가 소멸한다.

    현재 블럭스        예: 1,999
    얻는 배수          +1
    버려지는 양        999  ← 이게 없으면 유저가 모르고 날린다
    환생 후 상태       힘 · 레벨 · maxStage 초기화

"버려지는 양"을 강조 표시한다. 이 창에서 유저가 실제로 판단하는 것은
"지금 누를까 999 더 모을까" 하나뿐이다.

⚠️ 환생 버튼은 되돌릴 수 없는 동작이다. 확인 단계를 둔다.

### 제작 우선순위
```
1순위 (없으면 게임이 안 돌아감)
  HUD 전부 / 3D 안내 / 클리어 선택 / 실패 / 로딩 / 상점 / 환생

2순위 (없으면 돈을 못 범)
  로벅스 상품 구좌 / 오프라인 수령

3순위 (없어도 출시 가능)
  월드 / 크래프팅 연출 / 첫 접속 안내 / 리더보드
```

위에서부터 만든다. 언제든 "여기까지만 하고 내보내자"가 가능해야 한다.

### 뽑기 3종은 따로 만든다
탭으로 묶지 않는다. 셋이 필요한 공간이 다르기 때문.
- 아우라 — 캐릭터에 장착한 모습을 크게 봐야 함 → 큰 창
- 펫 — 보유 50마리 격자 + 장착 슬롯 6칸 동시 표시 → 큰 창
- 타이틀 — 목록만 필요 → 작은 창

대신 껍데기는 반드시 공유한다.

## 2. 세이프존

기준 해상도 1920 × 1080 (16:9 가로).
로블록스는 모바일에서도 가로 모드.

```
[건드릴 수 없음]  좌상단 — 로블록스 기본 UI가 차지

[코어 루프]       상단 중앙 — 스테이지 · 타이머
                하단 중앙 — 힘 수치 · 진행 바

[메뉴]           좌측 — 블럭스 보유량, 메뉴 아이콘

[판매]           우측 — 로벅스 상품 상시 노출
                하단 — 로벅스 구매 구좌 + 자동 토글

[3D]             발판·벽 위 BillboardGui. 화면 UI 아님

[절대 금지]       화면 중앙 — 캐릭터와 블록이 보여야 함
```

### 구역 비율

레퍼런스 기준 초안. G4 더미 HUD에서 실측 후 확정한다.

```
좌측 레일   폭 20%
우측 레일   폭 20%
상단 정보   높이 15%
하단 띠     높이 25%
중앙 금지   나머지
```

### ⚠️ 하단 띠가 가장 붐빈다

하단 25%에 들어가는 것:

    힘 · 레벨 · 속도 블록 (중앙)
    로벅스 구매 구좌 4개 (우측)
    자동 클리커 토글 / 자동 진행 버튼 (우측)

G4 더미 HUD 실측에서 가장 먼저 깨질 곳이다. 하단 25%가 부족하면
구역 비율을 조정하거나 로벅스 구좌 개수를 줄인다.
힘 수치와 이동 속도는 줄일 수 없다 — 코어 루프에 직접 쓰인다.

### 규칙
- 가장자리에서 화면 폭의 3% 안쪽으로 여백. 폰 둥근 모서리 대응
- 중앙 금지 구역에는 화면 UI를 두지 않는다
- 3D 오브젝트에 붙는 BillboardGui는 금지 구역 규칙의 예외

⚠️ 기존 규칙 "3D 월드의 안내 문구도 금지 구역 밖으로 뺀다"는 폐기했다.
발판과 벽이 화면 중앙에 위치하므로 그 위 안내는 중앙에 뜰 수밖에 없다.
대신 화면 UI가 그 영역을 침범하지 않는 것으로 겹침을 방지한다.

### 왜 힘이 하단이고 블럭스가 좌상단인가

성장하는 값은 크게 아래, 쌓아두는 값은 작게 위.

```
블럭스   환생 재료. 천천히 쌓이고 자주 안 본다     → 좌상단, 작게
힘       방치로 매초 오른다. 계속 본다             → 하단, 특대
```

이번 런의 획득 보상은 발판 위 BillboardGui에 표시되므로 HUD에 넣지 않는다.
좌상단 블럭스(보유 총량)와 발판 위 보상(이번 런)은 서로 다른 값이다.

## 3. 색

역할별로 배정한다. 예쁜 색을 고르는 게 아니다.
0.5초컷 구간에서는 글자를 읽을 시간이 없어 색으로만 판단한다.

⚠️ **아래 표의 역할 명칭이 이 프로젝트의 유일한 색 이름이다.**
다른 문서에서도 이 명칭 그대로 쓴다. 같은 색을 문서마다 다르게 부르면
(수령·확정 / 수령·안전 / 확정 노랑 …) 화면이 이만큼 늘어났을 때
"이 노랑이 그 노랑인가"를 매번 되묻게 되고, 그 확인 비용이 화면 수만큼 곱해진다.
색 하나에 이름 하나, 역할 하나. 쓰임새는 이름 뒤에 덧붙이되 이름을 바꾸지 않는다.

| 역할 | 밝은 | 기본 | 어두운 |
|---|---|---|---|
| 힘 (주황) | `#FFB347` | `#FF8C1A` | `#C25E00` |
| 블럭스 (하늘) | `#7DD3FC` | `#38A8E8` | `#1668A8` |
| 진행 · 도박 (보라) | `#C77DFF` | `#9D4EDD` | `#5A189A` |
| 수령 · 안전 (노랑) | `#FFE066` | `#FFC61A` | `#C28F00` |
| 로벅스 (초록) | `#86EFAC` | `#3FBF5F` | `#1F7A38` |
| 경고 · 닫기 · 실패 (빨강) | `#FF8080` | `#E63946` | `#A11D28` |
| 프리미엄 (남색+금테) | `#4A6FA5` | `#2C4A78` | `#16294A` |
| 중립 (회색) | `#E8E8E8` | `#B0B0B0` | `#6B6B6B` |

### 3D 오브젝트 색 배정

화면 버튼과 3D 오브젝트가 같은 뜻이면 같은 색을 쓴다.

| 오브젝트 | 역할 (= 위 표) | 성격 |
|---|---|---|
| 수령 발판 | 수령 · 안전 (노랑) | 선택 |
| 진행 벽 | 진행 · 도박 (보라) | 선택 |
| 클릭 파워 패드 | 힘 (주황) | 성장 |
| 클릭 파워 패드 (미해금) | 중립 (회색) | 잠김 |

패드가 주황인 이유: 패드는 클릭당 힘 증가량을 바꾸는 물건이다.
힘을 키우는 것에 힘 색을 쓰는 게 가장 짧은 설명이다.

노랑·보라는 "둘 중 하나를 고른다"는 뜻으로 이미 묶여 있다. 패드는
고르는 대상이 아니라 밟고 지나가며 성장시키는 것이라 성격이 다르다.
같은 색을 쓰면 유저가 패드도 선택지로 착각한다.

미해금 패드는 중립(회색)이다. 위 표에 이미 "비활성 · 잠김"으로
배정돼 있어 새 색을 만들 필요가 없다.

⚠️ "힘(주황)은 버튼 색이 아니다"는 규칙은 그대로다. 패드는 버튼이
   아니라 3D 오브젝트다. 화면 버튼에는 여전히 주황을 쓰지 않는다.

### 진행을 빨강으로 하지 않은 이유
빨강은 닫기·경고·실패에 이미 강하게 묶여 있다.
진행은 유저가 신나서 고르는 선택인데 빨강은 "하지 마"로 읽혀 손이 멈칫한다.
실패 화면도 빨강이라 "빨강 = 망하는 것"으로 학습되면 진행을 안 고르게 된다.

노랑(안전하게 챙긴다) vs 보라(위험을 걸고 더 간다).
둘 다 긍정적인 색이라 진짜로 고민하게 된다. 푸시-유어-럭에 필요한 상태.

이 색 대비는 3D 발판·벽과 그 위 BillboardGui에도 그대로 적용한다.

### 세 단계를 쓰는 법
버튼 하나에 전부 들어간다.
- 바탕 = 기본
- 위쪽 하이라이트 = 밝은색
- 테두리와 아래 그림자 = 어두운색

### 힘과 블럭스를 나눈 이유
2트랙 구조. 유저가 "이건 힘 관련, 이건 블럭스"를 색으로 구분하게 만든다.

## 4. 글자

### 크기 5단계

| 단계 | 화면 높이 대비 | 1080 기준 | 쓰이는 곳 |
|---|---|---|---|
| 특대 | 7% | 76px | 힘 수치, 타이머 |
| 대 | 5% | 54px | 창 제목, 주요 버튼 |
| 중 | 3.5% | 38px | 항목 이름, 가격 |
| 소 | 2.5% | 27px | 부가 설명, 단위 |
| 극소 | 2% | 22px | 각주, 확률 |

단계 사이를 넉넉히 벌렸다. 특대와 대가 비슷하면 뭐가 중요한지 안 보인다.
이 다섯 개 밖으로 나가지 않는다. 강조는 크기 대신 색이나 굵기로.

### 로블록스 적용법
```
Size → Y → Scale 에 비율 입력, Offset 은 0
TextScaled 켜기
```
`Offset`은 픽셀 고정이라 폰에서 깨진다. 반드시 `Scale`을 쓴다.

⚠️ `TextScaled`는 프레임을 꽉 채우도록 글자를 늘리므로,
실제 크기를 결정하는 것은 프레임 높이다.
즉 위 5단계는 글자 크기가 아니라 **프레임 높이 규격**이다.

자릿수가 늘어나면 `TextScaled`가 글자를 줄여 특대가 중처럼 보이는 구간이 생긴다.
`UITextSizeConstraint`로 상한을 걸어 방지한다.

### 외곽선
흰 글자 + 검은 스트로크. 3D 배경이 뭐가 되든 읽히게 한다. 필수.

### 숫자가 UI 최대 제약

`1.23Qa`, `4.56ab`, `7.89AB` 형식이 HUD 곳곳에 뜨고 자릿수가 계속 변한다.

```
최대 폭 기준   999.99AB  (8자)
```

모든 숫자 칸은 이 폭으로 설계한다. 딱 맞게 만들면 나중에 잘린다.
표기 규칙은 `DESIGN.md` "4. 숫자 표기" 참조.

참고 게임 1이 정확히 여기서 무너졌다 (숫자 뒷부분 잘림).

### 폰트 (미해결)
로블록스 내장 폰트 중 한글이 든 두꺼운 폰트가 사실상 없다.
Fredoka One 등 선택 시 한글만 다른 폰트로 자동 대체되어 굵기가 어긋난다.

```
현재  Source Sans Pro (임시. 한글/숫자 굵기는 안 어긋남)
목표  눈누 상업용 무료 폰트 업로드
      후보 — 어그로체 / 배민 도현체 / 여기어때 잘난체
      조건 — 상업용 무료, 굵은 굵기 있을 것
```

⚠️ "상업용 무료"와 "제품에 임베딩·재배포 가능"은 다른 조건이다.
로블록스 업로드는 임베딩에 해당하므로 후보별 라이선스 전문 확인이 필요하다.

업로드는 희준 작업. 폰트는 나중에 한 번에 교체 가능하므로 U2 진행을 막지 않는다.

## 5. 버튼

### 9-slice

버튼 이미지 한 장으로 모든 크기를 커버한다.
그냥 늘리면 테두리와 둥근 모서리까지 늘어나 뭉개진다.

```
┌───┬─────────┬───┐
│ ① │    ②    │ ③ │   모서리 ①③⑦⑨  안 늘어남
├───┼─────────┼───┤   가로변 ②⑧      가로로만
│ ④ │    ⑤    │ ⑥ │   세로변 ④⑥      세로로만
├───┼─────────┼───┤   가운데 ⑤        양방향
│ ⑦ │    ⑧    │ ⑨ │
└───┴─────────┴───┘
```

```
원본 크기     192 × 64
모서리 여백   24px 고정
```

테두리, 둥근 모서리, 하이라이트가 전부 24px 안에 들어가야 한다.
피그마에서 사방 24px 가이드선을 먼저 긋고 작업한다.

⚠️ 버튼 PNG에 레고 텍스처를 넣지 않는다. 늘리면 돌기 간격이 깨진다.

### 구조 (3층)
```
┌─────────────────┐  ← 어두운색 테두리 3~4px
│  밝은색 하이라이트  │  ← 위쪽 1/3
│    기본색 바탕    │
└─────────────────┘  ← 어두운색 그림자 (아래)
```
위가 밝고 아래가 어두우면 빛이 위에서 오는 것처럼 느껴져 튀어나와 보인다.

### 색 6종

역할 명칭은 "3. 색" 표와 동일하다. 쓰임새만 덧붙인다.

| 파일 | 역할 (= 3. 색) | 쓰임새 |
|---|---|---|
| `btn_yellow` | 수령 · 안전 (노랑) | 수령 선택, 확정·확인 |
| `btn_purple` | 진행 · 도박 (보라) | 진행 선택, 워프 구매 |
| `btn_blue` | 블럭스 (하늘) | 블럭스 소비 — 업그레이드, 롤 |
| `btn_green` | 로벅스 (초록) | 로벅스 결제 |
| `btn_red` | 경고 · 닫기 · 실패 (빨강) | 창 닫기 |
| `btn_gray` | 중립 (회색) | 비활성 · 잠김 |

힘 (주황)은 버튼이 없다. 재화 표시와 아이콘에만 쓰인다.

### 상태 3종은 PNG를 그리지 않는다

```
기본     원본 그대로
눌림     ImageColor3 를 어둡게 + 1~2px 아래로
비활성   btn_gray 로 교체
```

전부 코드에서 처리한다. 지환은 기본 상태 6장만 그린다.

### 크기 2종
```
큰 버튼   화면 높이의 9%   — 창 안 주요 액션
작은 버튼 화면 높이의 6%   — 닫기, 목록 안 구매 버튼
```
9%는 모바일 엄지 터치 최소 크기.

### 비율 고정이 필요한 요소

`Scale`은 X가 부모 너비, Y가 부모 높이 기준이라 화면비가 바뀌면 정사각형이 깨진다.
아이콘 타일처럼 비율이 고정돼야 하는 요소는 `UIAspectRatioConstraint`를 함께 건다.
명세에 "비율 고정" 여부를 표시한다.

## 6. 패널

### 크기 2종
```
작은 창  화면의 60% × 70%
         상점 · 환생 · 드론 · 설정 · 타이틀 · 코드 · 출석 · 워프 · 월드
         자동 진행 설정

큰 창    화면의 85% × 85%
         아우라 · 펫
```

### 2층 구조

패널만 텍스처를 쓴다. 버튼과 달리 두 층으로 나눈다.

```
아래층   texture_lego.png    ScaleType = Tile
         → 늘려도 무늬 크기가 유지된다

위층     panel_frame.png     ScaleType = Slice
         → 가운데가 투명이라 아래 텍스처가 비쳐 보인다
```

이러면 어떤 크기에서도 테두리 굵기와 무늬 간격이 둘 다 안 깨진다.
텍스처는 상하좌우로 이어붙여도 이음매가 보이지 않아야 한다.

### 껍데기는 완전히 동일
```
제목    위쪽 가운데, 대(5%)
X 버튼  오른쪽 위 구석, 작은 버튼(6%)
본문    나머지 전부
```

창을 몇 개를 열어도 제목과 X가 항상 같은 자리에 있어야 한다.
참고 게임 2가 잘된 이유가 정확히 이것. 실력이 아니라 규칙의 차이다.

### 여백
패널 테두리와 내용물 사이 = 화면 폭의 2%. 항목끼리도 같은 값.
여백을 하나로 통일하면 아무렇게나 배치해도 정돈돼 보인다.

### 모달 뜨면 배경 흐리게
지금 뭘 보고 있는지가 명확해진다.

### 레이어 우선순위 (미정)

오프라인 수령, 클리어 선택, 실패, 토스트가 동시에 뜨려 할 때의 순서와
대기열 규칙이 아직 없다. U4 착수 전까지 정한다.

## 7. 아이콘

### 타일 규격
```
정사각형   화면 높이의 8%  (UIAspectRatioConstraint 필수)
안쪽 그림  타일의 70% (사방 15% 여백)
아래 라벨  소(2.5%), 한글 2~4자
테두리    어두운색 3px
원본 크기  256 × 256
```
그림을 타일에 꽉 채우면 답답하고 아이콘끼리 붙어 보인다.

### 그리는 규칙
- 정면에서 본 모습. 비스듬한 각도 금지 (섞이면 지저분)
- 굵은 검은 외곽선
- 단순하게. 폰에서는 실루엣만 남는다
- 색은 두세 개까지. 많으면 작을 때 뭉개진다

### 필요 목록 (17개)

**타일 아이콘 (16)** — 타일 위에 얹히고 그 자체가 탭 타겟이다. 위 "타일 규격"이 적용된다.
```
메뉴  icon_shop · icon_rebirth · icon_drone · icon_settings
      icon_aura · icon_title · icon_pet · icon_warp · icon_world
재화  icon_power · icon_blox
기타  icon_code · icon_attend · icon_close
자동  icon_autoclick · icon_autoadvance
```

**인라인 아이콘 (1)** — 값 표시 옆에 붙는 표시다. 타일에 얹지 않는다.
```
편집  icon_edit  (연필)
```

⚠️ `icon_edit`에는 위 **"타일 규격"이 적용되지 않는다.**
이동 속도 값 옆에 붙어 "이 값은 탭하면 바꿀 수 있다"를 알리는 표시이고,
실제 탭 타겟은 값 패널 전체다. 연필 자체는 눌리지 않는다
("1. 화면 목록 > 이동 속도 조절은 편의 기능이 아니다").
그리는 규칙(정면 · 굵은 검은 외곽선 · 단순 · 색 두세 개)만 타일 아이콘과 같다.
제작 규격은 `docs/UI_ASSET_SPEC.md` "4-2. 인라인 아이콘".

⚠️ `icon_power`와 `icon_blox`는 실루엣이 겹치면 안 된다.
둘 다 가로로 긴 사각형 계열이면 40px에서 구분이 안 된다.

### 검수
타일 아이콘 전부를 한 화면에 놓고 40px로 축소한다. 그 상태에서 서로 구분되면 통과.

## 9. 참고 게임 분석

| | 게임 1 (유사 장르) | 게임 2 (완성도 높음) |
|---|---|---|
| 창 제목 | 좌상단, 창마다 다름 | 상단 중앙, 전부 동일 |
| 닫기 버튼 | 우상단, 패널 밖으로 삐져나감 | 우상단, 항상 같은 자리 |
| 메뉴 아이콘 | 크기·비율 제각각 | 정사각형 타일로 통일 |
| 창 개수 | 기능마다 따로 | 탭으로 묶음 |
| 배경 처리 | 없음 | 흐리게 |

게임 2는 창을 여러 개 열어도 어디에 뭐가 있을지 예측이 된다.
차이는 실력이 아니라 규칙을 먼저 정했느냐다.

### 둘 다 실패한 것
3D 월드 텍스트와 UI가 겹친다.
우리는 화면 UI가 중앙 금지 구역을 침범하지 않는 것으로 방지한다.

### 레퍼런스에서 가져온 하단 구조

```
힘 수치 (특대)
레벨 진행 바 + 현재/다음 레벨
이동 속도 (현재 / 최대, 편집 가능)
로벅스 구매 구좌 4개
자동 클리커 토글 / 자동 진행 버튼
```

⚠️ "레벨 진행 바"는 원래 레퍼런스를 관찰해 적은 문장이었으나,
우리 게임에도 레벨 시스템이 실제로 생겼다. 정의는
"1. 화면 목록 > 힘 · 레벨 · 속도 블록" 참조.

레퍼런스는 하단 UI가 약 25%를 차지하지만 캐릭터와 겹치지 않는다.
카메라를 그만큼 위로 올려둔 결과다. 우리도 카메라 각도를 함께 잡아야 한다.

## 작업 흐름

```
피그마에서 시안 완성
   ↓ 이미지만 PNG로 내보내기 (버튼 배경, 아이콘, 패널 테두리, 텍스처)
   ↓ 관문 통과 확인 (G1~G3)
희준이 로블록스에 업로드 → ID 발급
   ↓ ID + 레이아웃 명세
코드로 배치
   ↓
Team Create에서 확인 → 수정 요청 (숫자로)
```

디자인 담당 산출물 = PNG 조각 + 3D 파트 + "이건 여기, 이 크기로" 명세.
피그마에서 그릴 때부터 "이건 이미지로 뽑는다 / 이건 코드가 그린다"를 구분해둔다.

명세 템플릿은 `docs/UI_HANDOFF.md` 참조.
