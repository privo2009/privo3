# 대기 큐

결정됐으나 아직 반영되지 않은 것들. 세션을 넘어 누적된다.
세션에 무엇을 했는지는 `HANDOFF/`에 있다 — 여기는 **아직 안 끝난 것**만 둔다.

⚠️ 항목이 해소되면 지우고, 어디에 반영됐는지 커밋 해시를 남긴다.
   쌓이기만 하면 아무도 안 읽는다.

`docs/UI_HANDOFF.md`와 합치지 않는다. 그것은 인계 절차와 검증 관문 문서이고
이것은 대기 큐다. 성격이 다르다.

문서 갱신: 2026-08-26

## 지환 쪽 — 전달 보류 중

G1(btn_yellow) 진행 중. **U2 진입 시점에 전달한다.**

```
파일   docs/UI.md, docs/UI_ASSET_SPEC.md, docs/UI_HANDOFF.md
내용   아이콘 17종 결정 + 연필 규격 예외 + panel_value 안내
```

⚠️ **여전히 유효한 경고다** (08-26 재확인). `ea3c681`이 08-26으로 올린 것은
CLAUDE·ROADMAP·DESIGN이고 아래 세 문서는 건드리지 않았다:

```
docs/UI.md              문서 갱신: 2026-08-22
docs/UI_ASSET_SPEC.md   문서 갱신: 2026-08-22
docs/UI_HANDOFF.md      "문서 갱신" 줄 자체가 없다  ← 더 나쁘다
```

날짜만으로 갱신본 구분이 안 된다. **전달 전 날짜를 고치고,
`UI_HANDOFF.md`에는 날짜 줄을 새로 넣을 것.**

### 신규 — 클릭 파워 패드 파트

```
개수      24개 (월드1). 월드마다 다름
크기      8 x 1 x 8 studs (초안. 실제 파트 바운딩 박스로 교체)
배치      일렬. 앞으로 갈수록 강해진다
상태      해금 / 미해금 2종
색        ⚠️ 수령 발판(노랑) · 진행 벽(보라)과 반드시 구분.
          두 색은 이미 의미가 배정돼 있다 (docs/UI.md "3. 색")
표시      BillboardGui — 클릭 파워 + 해금 조건
```

교체 지점은 `PadService.createPadPart` 위 주석에 명시돼 있다.
유지해야 할 계약 3가지: `Anchored = true` / `CanCollide = false` /
`Touched` 연결과 `PadIndex` Attribute.

### 신규 — 수령 발판 · 진행 벽 최소 깊이

```
진행 방향 깊이   8 studs 이상   (필수 제약)
가로폭 · 높이    자유
```

이 값이 캐릭터 이동속도 상한을 직접 결정한다.
깊이를 줄이면 상한이 같은 비율로 내려간다 — 4 studs면 상한 40이 된다.
깊이만 하한이 있고 나머지 치수는 제약이 없다.
(근거 → `DESIGN.md` "레벨 > MAX_WALK_SPEED는 상수가 아니다")

- **테스트 393은 소스의 `check(` 호출을 센 정적 값이다.** 6개 파일은
  08-22 실측값을 그대로 뒀다. Studio Play 런타임 출력과 미대조
- **4-2-c 커밋 2개가 Studio Play 미검증이다** (RC 사용 중이라 Play 불가).
  다음 Play에서 확인할 것:
  ```

  SpeedService   [SpeedServiceTests] 21 passed
  전체 합계       422

  ```

  어긋나면 런타임 실측값으로 ROADMAP 표를 고치고 "최근 갱신"에 명시한다.
  ⚠️ ROADMAP 표는 아직 393에 멈춰 있다 — 정적 카운트를 겹쳐 얹지 않으려고
  일부러 두었다. 다음 Play 출력으로 한 번에 맞춘다
