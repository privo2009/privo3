# UI 에셋 제작 규격서

문서 갱신: 2026-08-22

> **대상**: 디자인 담당(지환)
> **범위**: 피그마에서 **무엇을 / 어떤 크기로** 그려서 내보내는지만 적는다.
> 로블록스나 코드를 몰라도 이 문서만 보고 작업할 수 있어야 한다.
>
> 색·아이콘 형태 등 "무엇을 그리는가"의 원본은 `docs/UI.md`다.
> 이 문서는 "어떤 규격으로 내보내는가"만 다룬다. 둘이 어긋나면 UI.md가 맞다.
>
> 파일 전달 절차와 검증 관문은 `docs/UI_HANDOFF.md` 참조.

## 0. 공통 규칙

```
형식      PNG
배경      투명 (흰색 아님)
색 모드   RGBA
```

**파일명** — 소문자 + 언더스코어 + 영문만. 한글·공백·대문자 금지.

```
O   btn_yellow.png    icon_power.png    texture_lego.png
X   버튼_노랑.png     Btn Yellow.png    icon-power.png
```

**크기** — 실제 화면에 표시되는 크기보다 **크게** 그린다.
축소는 깨끗하게 되지만, 확대는 뭉개진다.
이 문서의 px 수치는 전부 그 "크게 그린" 값이므로 그대로 따르면 된다.

## 1. 9-slice — 이 문서에서 가장 중요한 항목

버튼과 패널은 크기가 제각각이다. 작은 버튼, 긴 버튼, 큰 창이 전부 나온다.
이미지 한 장을 그때그때 통째로 늘리면 테두리가 같이 두꺼워지고 모서리가 찌그러진다.

그래서 이미지를 **9칸으로 쪼개어** 칸마다 다르게 늘린다. 이게 9-slice다.

```
      ←24px→                          ←24px→
     ┌───────┬──────────────────────┬───────┐   ↑
     │   1   │          2           │   3   │  24px
     │ 안늘어│    가로로만 늘어남   │ 안늘어│   ↓
     ├───────┼──────────────────────┼───────┤
     │   4   │          5           │   6   │
     │세로로 │       양방향으로     │세로로 │  세로로
     │만늘어 │        늘어남        │만늘어 │  늘어남
     ├───────┼──────────────────────┼───────┤   ↑
     │   7   │          8           │   9   │  24px
     │ 안늘어│    가로로만 늘어남   │ 안늘어│   ↓
     └───────┴──────────────────────┴───────┘
              ←  가로로 늘어남  →
```

```
1 3 7 9 (모서리)  — 절대 안 늘어남. 원본 그대로 찍힘
2 8     (위·아래) — 가로로만 늘어남
4 6     (좌·우)   — 세로로만 늘어남
5       (가운데)  — 가로·세로 양방향으로 늘어남
```

### 규칙: 모서리 여백 24px 고정

**테두리, 둥근 모서리, 하이라이트가 전부 사방 24px 안에 들어가야 한다.**

24px를 넘어가는 순간 그 부분이 늘어나는 칸에 걸린다 →
큰 버튼에서만 테두리가 두꺼워지거나 모서리가 뭉개진다.

### 피그마 작업 순서

```
1. 캔버스를 만들고 사방 24px 위치에 가이드선 4개를 먼저 긋는다
2. 테두리 · 둥근 모서리 · 하이라이트는 전부 그 가이드선 안쪽에서 끝낸다
3. 가운데(5번 칸)는 단색 또는 아주 단순한 세로 그라데이션만
4. 가운데에 로고 · 글자 · 큰 무늬를 넣지 않는다 (늘어나면 찌그러진다)
```

24px는 버튼(192x64)과 패널(256x256) **양쪽에 동일 적용**한다.
값이 하나여야 코드에서도 실수가 안 난다.

## 2. 버튼 6종 — 각 192 x 64

9-slice 대상. 24px 규칙을 그대로 적용한다.

### 색값

출처: `docs/UI.md` "3. 색" 표 + "5. 버튼 > 색 6종" 표

| 파일명 | 역할 | 바탕 (기본) | 하이라이트 (밝은) | 테두리·그림자 (어두운) |
|---|---|---|---|---|
| `btn_yellow.png` | 수령 · 안전 (노랑) | `#FFC61A` | `#FFE066` | `#C28F00` |
| `btn_purple.png` | 진행 · 도박 (보라) | `#9D4EDD` | `#C77DFF` | `#5A189A` |
| `btn_blue.png` | 블럭스 (하늘) | `#38A8E8` | `#7DD3FC` | `#1668A8` |
| `btn_green.png` | 로벅스 (초록) | `#3FBF5F` | `#86EFAC` | `#1F7A38` |
| `btn_red.png` | 경고 · 닫기 · 실패 (빨강) | `#E63946` | `#FF8080` | `#A11D28` |
| `btn_gray.png` | 중립 (회색) | `#B0B0B0` | `#E8E8E8` | `#6B6B6B` |

**역할 이름은 위 표기가 전부다.** 다른 이름으로 바꿔 부르지 않는다
(`docs/UI.md` "3. 색"). 쓰임새는 아래처럼 이름 뒤에 덧붙인다.

```
btn_yellow (수령 · 안전) — 수령 선택, 확정·확인
btn_purple (진행 · 도박) — 진행 선택, 워프 구매
btn_blue   (블럭스)      — 업그레이드, 롤 등 블럭스 소비
btn_green  (로벅스)      — 로벅스 결제
btn_red    (경고 · 닫기 · 실패) — 창 닫기
btn_gray   (중립)        — 비활성 · 잠김
```

힘 (주황, 기본 `#FF8C1A`)은 **버튼 색이 아니다.** 재화 표시와 아이콘에만 쓴다.

수령 · 안전(노랑)과 진행 · 도박(보라)은 챌린지의 수령 발판 · 진행 벽과 **같은 색**이다.
화면 버튼과 3D 오브젝트가 같은 색이어야 유저가 같은 뜻으로 읽는다.
(`DESIGN.md` "1. 챌린지 → 선택 방식")

### 3층 구조 — 세 색을 한 버튼에 넣는 법

출처: `docs/UI.md` "5. 버튼 > 구조 (3층)"

```
┌─────────────────────┐  ← 어두운색 테두리 3~4px
│   밝은색 하이라이트    │  ← 위쪽 1/3
│      기본색 바탕      │
└─────────────────────┘  ← 어두운색 그림자 (아래)
```

위가 밝고 아래가 어두우면 빛이 위에서 오는 것처럼 느껴져 튀어나와 보인다.

하이라이트(위쪽 1/3 = 64px 중 약 21px)와 테두리는 **위아래 24px 밴드 안에서 끝난다.**
그래야 버튼이 세로로 늘어나도 하이라이트 두께가 그대로 유지된다.

### 넣지 말 것

```
X  레고 텍스처 · 무늬   (늘리면 돌기 간격이 깨진다. 텍스처는 패널에만)
X  글자                (버튼 이름은 코드가 얹는다)
X  눌린 / 마우스 올린 / 비활성 상태 변형
```

상태 3종은 전부 코드에서 처리한다 (`docs/UI.md` "5. 버튼 > 상태 3종").

```
기본     원본 그대로
눌림     색을 어둡게 + 1~2px 아래로
비활성   btn_gray 로 교체
```

지환은 **기본 상태 6장만** 그린다. 상태별로 파일을 만들면 6종이 18종이 된다.
`btn_gray`는 "비활성 변형"이 아니라 독립된 색 1종이다.

## 3. 패널 · 타일

### panel_frame.png — 256 x 256

```
9-slice 대상 (24px 규칙 적용)
가운데는 완전 투명. 테두리만 그린다
```

가운데를 비우는 이유: 창 안쪽에는 `texture_lego.png`를 따로 깔아
**2층 구조**로 만든다. 테두리와 무늬가 한 장이면 창 크기가 바뀔 때 무늬까지 늘어난다.

### texture_lego.png — 128 x 128

```
타일처럼 반복해서 까는 무늬
이음매가 보이면 안 된다 (위쪽 끝과 아래쪽 끝, 왼쪽 끝과 오른쪽 끝이 이어져야 함)
```

검수: 피그마에서 3x3으로 붙여놓고 격자선이 보이는지 본다. 보이면 실패.

### tile_icon.png — 128 x 128

```
아이콘 뒤에 까는 배경 타일
아이콘보다 눈에 띄면 안 된다. 배경이지 주인공이 아니다
```

## 4. 아이콘 14종 — 각 256 x 256

| 파일명 | 뜻 |
|---|---|
| `icon_shop.png` | 상점 |
| `icon_rebirth.png` | 환생 |
| `icon_drone.png` | 드론 |
| `icon_settings.png` | 설정 |
| `icon_aura.png` | 아우라 |
| `icon_title.png` | 타이틀 |
| `icon_pet.png` | 펫 |
| `icon_warp.png` | 워프 |
| `icon_world.png` | 월드 |
| `icon_power.png` | 힘 (재화) |
| `icon_blox.png` | 블럭스 (재화) |
| `icon_code.png` | 코드 입력 |
| `icon_attend.png` | 출석 |
| `icon_close.png` | 닫기 |

그리는 방식은 `docs/UI.md` **"7. 아이콘 > 그리는 규칙"** 을 그대로 따른다.

```
정면에서 본 모습. 비스듬한 각도 금지
굵은 검은 외곽선
단순하게 — 폰에서는 실루엣만 남는다
색은 두세 개까지
```

아이콘 그림은 타일의 **70%** 만 채운다 (사방 15% 여백).
꽉 채우면 답답하고 아이콘끼리 붙어 보인다. (`docs/UI.md` "7. 아이콘 > 타일 규격")

### 추가 제약 하나

**`icon_power`와 `icon_blox`는 실루엣이 겹치면 안 된다.**

둘 다 가로로 긴 사각형 계열이면 40px에서 구분이 안 된다 (`docs/UI.md` "7. 아이콘").

이 둘은 항상 화면에 떠 있는 재화 아이콘인데, **서로 떨어진 자리에 놓인다.**

```
블럭스   좌상단, 작게    (보유 총량. 천천히 쌓인다)
힘       하단 중앙, 특대  (방치로 매초 오른다)
```

(`docs/UI.md` "2. 세이프존 > 왜 힘이 하단이고 블럭스가 좌상단인가")

나란히 있으면 서로 비교해서 구분할 수 있지만, 떨어져 있으면 **각각 단독으로**
무엇인지 읽혀야 한다. 그래서 제약이 더 세다.

검수: 두 아이콘을 검은색 단색으로 칠하고 40px로 줄인다.
색을 빼고 형태만으로 구분되면 통과.

## 5. 3D 에셋 — PNG 아님

챌린지의 **수령 발판**과 **진행 벽**은 그림이 아니라 3D 오브젝트다.
Studio(Team Create)에서 Part로 직접 만든다.

| 오브젝트 | 역할 (= 색) | 유저 동작 |
|---|---|---|
| 수령 발판 | 수령 · 안전 (노랑) `#FFC61A` | 밟는다 |
| 진행 벽 | 진행 · 도박 (보라) `#9D4EDD` | 통과한다 |
| 클릭 파워 패드 | 힘 (주황) `#FF8C1A` | 밟고 지나간다 |
| 클릭 파워 패드 (미해금) | 중립 (회색) `#B0B0B0` | 밟아도 반응 없음 |

패드는 여러 개가 바닥에 깔리고 월드마다 세트가 교체된다.
위에 BillboardGui 2줄이 뜬다 — 클릭 파워(위) / 해금 조건(아래).
글자는 코드가 붙인다.

해금 여부는 색으로만 구분한다. 형태는 동일하게 만든다.

```
색 기준     docs/UI.md "3. 색" (버튼 btn_yellow / btn_purple과 동일)
위 글자     코드가 붙인다. 디자인은 형태와 색만
PNG 필요    없음
```

근거: `DESIGN.md` "1. 챌린지 → 선택 방식 — 둘 다 3D 오브젝트"

## 7. 내보내기 전 검수

```
[ ] 40px로 축소해도 무엇인지 구분되는가
[ ] 9-slice 대상(버튼 6종, panel_frame)의 테두리가 24px 안에 다 들어갔는가
[ ] 파일명이 소문자+언더스코어+영문인가
[ ] 배경이 실제로 투명인가 (흰색을 깔아둔 게 아닌가)
[ ] texture_lego를 3x3으로 붙였을 때 이음매가 안 보이는가
[ ] icon_power와 icon_blox가 검은 단색 40px에서 구분되는가
```

대량 제작 전에 `docs/UI_HANDOFF.md`의 **검증 관문 G1~G4**를 먼저 통과할 것.
