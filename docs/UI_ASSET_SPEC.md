## 0. 공통 규칙

```
형식      PNG
배경      투명 (흰색 아님)
색 모드   RGBA
```

**파일명** — 소문자 + 언더스코어 + 영문만. 한글·공백·대문자 금지.

```
O   btn_yellow.png    icon_power.png    texture_lego.png
X   버튼_노랑.png     Btn Yellow.png    icon-power.png
```

**크기** — 실제 화면에 표시되는 크기보다 **크게** 그린다.
축소는 깨끗하게 되지만, 확대는 뭉개진다.
이 문서의 px 수치는 전부 그 "크게 그린" 값이므로 그대로 따르면 된다.

## 1. 9-slice — 이 문서에서 가장 중요한 항목

버튼과 패널은 크기가 제각각이다. 작은 버튼, 긴 버튼, 큰 창이 전부 나온다.
이미지 한 장을 그때그때 통째로 늘리면 테두리가 같이 두꺼워지고 모서리가 찌그러진다.

그래서 이미지를 **9칸으로 쪼개어** 칸마다 다르게 늘린다. 이게 9-slice다.

```
      ←24px→                          ←24px→
     ┌───────┬──────────────────────┬───────┐   ↑
     │   1   │          2           │   3   │  24px
     │ 안늘어│    가로로만 늘어남   │ 안늘어│   ↓
     ├───────┼──────────────────────┼───────┤
     │   4   │          5           │   6   │
     │세로로 │       양방향으로     │세로로 │  세로로
     │만늘어 │        늘어남        │만늘어 │  늘어남
     ├───────┼──────────────────────┼───────┤   ↑
     │   7   │          8           │   9   │  24px
     │ 안늘어│    가로로만 늘어남   │ 안늘어│   ↓
     └───────┴──────────────────────┴───────┘
              ←  가로로 늘어남  →
```

```
1 3 7 9 (모서리)  — 절대 안 늘어남. 원본 그대로 찍힘
2 8     (위·아래) — 가로로만 늘어남
4 6     (좌·우)   — 세로로만 늘어남
5       (가운데)  — 가로·세로 양방향으로 늘어남
```

### 규칙: 모서리 여백 24px 고정

**테두리, 둥근 모서리, 하이라이트가 전부 사방 24px 안에 들어가야 한다.**

24px를 넘어가는 순간 그 부분이 늘어나는 칸에 걸린다 →
큰 버튼에서만 테두리가 두꺼워지거나 모서리가 뭉개진다.

### 피그마 작업 순서

```
1. 캔버스를 만들고 사방 24px 위치에 가이드선 4개를 먼저 긋는다
2. 테두리 · 둥근 모서리 · 하이라이트는 전부 그 가이드선 안쪽에서 끝낸다
3. 가운데(5번 칸)는 단색 또는 아주 단순한 세로 그라데이션만
4. 가운데에 로고 · 글자 · 큰 무늬를 넣지 않는다 (늘어나면 찌그러진다)
```

24px는 버튼 · 값 패널(192x64)과 창 패널(256x256) **양쪽에 동일 적용**한다.
값이 하나여야 코드에서도 실수가 안 난다.

## 2. 버튼 6종 — 각 192 x 64

9-slice 대상. 24px 규칙을 그대로 적용한다.

### 색값

출처: `docs/UI.md` "3. 색" 표 + "5. 버튼 > 색 6종" 표

| 파일명 | 역할 | 바탕 (기본) | 하이라이트 (밝은) | 테두리·그림자 (어두운) |
|---|---|---|---|---|
| `btn_yellow.png` | 수령 · 안전 (노랑) | `#FFC61A` | `#FFE066` | `#C28F00` |
| `btn_purple.png` | 진행 · 도박 (보라) | `#9D4EDD` | `#C77DFF` | `#5A189A` |
| `btn_blue.png` | 블럭스 (하늘) | `#38A8E8` | `#7DD3FC` | `#1668A8` |
| `btn_green.png` | 로벅스 (초록) | `#3FBF5F` | `#86EFAC` | `#1F7A38` |
| `btn_red.png` | 경고 · 닫기 · 실패 (빨강) | `#E63946` | `#FF8080` | `#A11D28` |
| `btn_gray.png` | 중립 (회색) | `#B0B0B0` | `#E8E8E8` | `#6B6B6B` |

**역할 이름은 위 표기가 전부다.** 다른 이름으로 바꿔 부르지 않는다
(`docs/UI.md` "3. 색"). 쓰임새는 아래처럼 이름 뒤에 덧붙인다.

```
btn_yellow (수령 · 안전) — 수령 선택, 확정·확인
btn_purple (진행 · 도박) — 진행 선택, 워프 구매
btn_blue   (블럭스)      — 업그레이드, 롤 등 블럭스 소비
btn_green  (로벅스)      — 로벅스 결제
btn_red    (경고 · 닫기 · 실패) — 창 닫기
btn_gray   (중립)        — 비활성 · 잠김
```

힘 (주황, 기본 `#FF8C1A`)은 **버튼 색이 아니다.** 재화 표시와 아이콘에만 쓴다.

수령 · 안전(노랑)과 진행 · 도박(보라)은 챌린지의 수령 발판 · 진행 벽과 **같은 색**이다.
화면 버튼과 3D 오브젝트가 같은 색이어야 유저가 같은 뜻으로 읽는다.
(`DESIGN.md` "1. 챌린지 → 선택 방식")

### 3층 구조 — 세 색을 한 버튼에 넣는 법

출처: `docs/UI.md` "5. 버튼 > 구조 (3층)"

```
┌─────────────────────┐  ← 어두운색 테두리 3~4px
│   밝은색 하이라이트    │  ← 위쪽 1/3
│      기본색 바탕      │
└─────────────────────┘  ← 어두운색 그림자 (아래)
```

위가 밝고 아래가 어두우면 빛이 위에서 오는 것처럼 느껴져 튀어나와 보인다.

하이라이트(위쪽 1/3 = 64px 중 약 21px)와 테두리는 **위아래 24px 밴드 안에서 끝난다.**
그래야 버튼이 세로로 늘어나도 하이라이트 두께가 그대로 유지된다.

### 넣지 말 것

```
X  레고 텍스처 · 무늬   (늘리면 돌기 간격이 깨진다. 텍스처는 패널에만)
X  글자                (버튼 이름은 코드가 얹는다)
X  눌린 / 마우스 올린 / 비활성 상태 변형
```

상태 3종은 전부 코드에서 처리한다 (`docs/UI.md` "5. 버튼 > 상태 3종").

```
기본     원본 그대로
눌림     색을 어둡게 + 1~2px 아래로
비활성   btn_gray 로 교체
```

지환은 **기본 상태 6장만** 그린다. 상태별로 파일을 만들면 6종이 18종이 된다.
`btn_gray`는 "비활성 변형"이 아니라 독립된 색 1종이다.

## 3. 패널 · 타일

### panel_frame.png — 256 x 256

```
9-slice 대상 (24px 규칙 적용)
가운데는 완전 투명. 테두리만 그린다
```

가운데를 비우는 이유: 창 안쪽에는 `texture_lego.png`를 따로 깔아
**2층 구조**로 만든다. 테두리와 무늬가 한 장이면 창 크기가 바뀔 때 무늬까지 늘어난다.

### panel_value.png — 192 x 64

```
9-slice 대상 (24px 규칙 적용)
가운데는 채운다. 비우지 않는다
```

HUD의 값 표시 배경이다. "값이 보이고 탭하면 편집되는" 요소에 쓴다.
첫 사용처는 이동 속도 표시 (`docs/UI.md` "1. 화면 목록 > 힘 · 레벨 · 속도 블록").

**왜 panel_frame을 쓰지 않는가** — panel_frame은 창용이라 테두리가 두껍다.
하단 띠는 힘·레벨·속도 블록 + 로벅스 구좌 + 자동 토글이 한꺼번에 들어가는,
G4에서 가장 먼저 깨질 구역이다 (`docs/UI.md` "2. 세이프존 > 하단 띠가 가장 붐빈다").
두꺼운 테두리를 작은 값 칸에 쓰면 안쪽 글자 자리가 줄고 띠가 더 답답해진다.

**크기 192 x 64 — 버튼과 같은 캔버스인 이유.**
값 칸은 세로로 얇고 가로로 긴 모양이라 버튼과 비율이 같다.
캔버스를 맞추면 버튼 작업 파일의 24px 가이드선을 그대로 쓸 수 있고,
9-slice 값이 프로젝트 전체에서 24px 하나로 유지된다 ("1. 9-slice").

**9-slice를 적용하는 이유.**
이동 속도는 3~4자리로 변하고 같은 배경을 다른 값 표시에도 재사용한다.
가로 폭이 고정되지 않으므로 통째로 늘리면 테두리가 같이 두꺼워진다.

**가운데를 채우는 이유.**
panel_frame은 안쪽에 texture_lego를 까는 2층 구조라 비워야 하지만,
panel_value 위에는 값 글자가 얹힌다. 배경이 비어 있으면 뒤의 3D 월드가
그대로 비쳐 흰 글자가 안 읽힌다.

```
가운데   중립 (회색) 어두운 값, 불투명도 80%
테두리   중립 (회색) 기본 값, 2px
```

색값은 `docs/UI.md` "3. 색" 표의 **중립 (회색)** 항목을 본다.
이동 속도는 재화도 도박도 아닌 설정값이라 중립으로 확정했다.

**3층 구조(하이라이트 · 그림자)를 넣지 않는다.**
넣으면 버튼으로 읽혀서 같은 띠에 있는 로벅스 구좌 · 자동 토글과 경쟁한다.
탭할 수 있다는 신호는 옆에 붙는 `icon_edit`(연필)이 담당하고,
실제 탭 타겟은 이 패널 전체다.

### texture_lego.png — 128 x 128

```
타일처럼 반복해서 까는 무늬
이음매가 보이면 안 된다 (위쪽 끝과 아래쪽 끝, 왼쪽 끝과 오른쪽 끝이 이어져야 함)
```

검수: 피그마에서 3x3으로 붙여놓고 격자선이 보이는지 본다. 보이면 실패.

### tile_icon.png — 128 x 128

```
아이콘 뒤에 까는 배경 타일
아이콘보다 눈에 띄면 안 된다. 배경이지 주인공이 아니다
```

## 4. 아이콘 16종

`icon_drone`은 드론 폐기(2026-10-21 사람 결정)로 제작 목록에서 뺐다. 이미 그렸다면 쓰이지 않는다.

아이콘은 **성격이 두 가지**고 규격이 서로 다르다. 그래서 절을 나눈다.

```
타일 아이콘 15종   tile_icon 위에 얹힌다. 그 자체가 탭 타겟   256 x 256
인라인 아이콘 1종   값 표시 옆에 붙는 표시. 탭 타겟이 아님    128 x 128
```

한 표에 16줄로 몰아넣으면 연필 한 줄이 나머지 15종의 규격
(256 · 타일 · 70% 여백)으로 만들어진다. 표 안의 한 줄짜리 예외는 반드시 놓친다.
규격이 다르면 절을 나눈다.

| `icon_rebirth.png` | 환생 |
| `icon_settings.png` | 설정 |

| `icon_code.png` | 코드 입력 |
| `icon_attend.png` | 출석 |
| `icon_close.png` | 닫기 |
| `icon_autoclick.png` | 자동 클리커 토글 |
| `icon_autoadvance.png` | 자동 진행 |

그리는 방식은 `docs/UI.md` **"7. 아이콘 > 그리는 규칙"** 을 그대로 따른다.

```
정면에서 본 모습. 비스듬한 각도 금지
```

아이콘 그림은 타일의 **70%** 만 채운다 (사방 15% 여백).
꽉 채우면 답답하고 아이콘끼리 붙어 보인다. (`docs/UI.md` "7. 아이콘 > 타일 규격")

#### 자동 토글 2종이 글자 라벨이 아니라 아이콘인 이유

`icon_autoclick` · `icon_autoadvance`는 하단 우측에 놓인다
(`docs/UI.md` "2. 세이프존 > 하단 띠가 가장 붐빈다").

```
하단 우측은 엄지가 닿는 자리다. 아이콘 타일이 탭 타겟이 크고 오조작이 적다
글자 라벨을 섞으면 하단 띠에 아이콘과 텍스트가 혼재해 어수선해진다
```

**켜짐 / 꺼짐 상태는 그리지 않는다. 기본형 1장씩만 그린다.**
버튼 상태 3종과 똑같은 구조다 — 상태는 코드가 처리한다 ("2. 버튼 6종 > 넣지 말 것").
상태별로 파일을 만들면 2종이 4종, 6종으로 늘어난다.

#### 추가 제약 하나

**`icon_power`와 `icon_blox`는 실루엣이 겹치면 안 된다.**

둘 다 가로로 긴 사각형 계열이면 40px에서 구분이 안 된다 (`docs/UI.md` "7. 아이콘").

이 둘은 항상 화면에 떠 있는 재화 아이콘인데, **서로 떨어진 자리에 놓인다.**

```
블럭스   좌상단, 작게    (보유 총량. 천천히 쌓인다)
힘       하단 중앙, 특대  (방치로 매초 오른다)
```

(`docs/UI.md` "2. 세이프존 > 왜 힘이 하단이고 블럭스가 좌상단인가")

나란히 있으면 서로 비교해서 구분할 수 있지만, 떨어져 있으면 **각각 단독으로**
무엇인지 읽혀야 한다. 그래서 제약이 더 세다.

검수: 두 아이콘을 검은색 단색으로 칠하고 40px로 줄인다.
색을 빼고 형태만으로 구분되면 통과.

### 4-2. 인라인 아이콘 1종 — 128 x 128

| 파일명 | 뜻 |
|---|---|
| `icon_edit.png` | 이동 속도 편집 (연필) |

⚠️ **연필은 버튼이 아니다.**
이동 속도 값 표시(`panel_value`) 옆에 붙어 "이 값은 탭하면 바꿀 수 있다"를
알리는 표시일 뿐이고, 실제 탭 타겟은 값 패널 전체다.
(`docs/UI.md` "1. 화면 목록 > 이동 속도 조절은 편의 기능이 아니다")

그래서 타일 아이콘 15종과 세 가지가 다르다.

```
타일에 얹지 않는다     tile_icon.png를 뒤에 깔지 않는다
70% 여백 규칙 없음     캔버스를 90%까지 채운다
크기가 작다           256이 아니라 128
```

**타일에 얹지 않는 이유.**
타일은 "여기를 눌러라"는 표시다. 연필에 타일을 깔면 탭 타겟이 두 개
(연필 타일 + 값 패널)로 보인다. 실제로 눌리는 것은 값 패널 하나다.

**70% 여백을 적용하지 않는 이유.**
사방 15% 여백은 타일 안에서 아이콘끼리 붙어 보이지 않게 하는 규칙이다.
연필은 타일도 없고 옆에 다른 아이콘도 없다. 표시 크기가 이미 작아서
여기에 15%를 더 비우면 실제 그림이 절반 이하로 남아 연필로 안 읽힌다.
검은 외곽선이 잘리지 않을 만큼(사방 5% 정도)만 비우고 나머지는 채운다.

**128인 이유.**
표시 크기가 이동 속도 글자 높이와 같다 — `docs/UI.md` "4. 글자 > 크기 5단계"의
소~중 구간이고, 타일 아이콘의 표시 크기(화면 높이 8%)보다 한참 작다.
128이면 그 표시 크기의 3배 이상이라 축소만 일어난다 ("0. 공통 규칙 > 크기").
256으로 만들면 표시 대비 8배가 되어 파일만 무거워지고 더 선명해지지는 않는다.

그리는 규칙(정면 · 굵은 검은 외곽선 · 단순 · 색 두세 개)은 타일 아이콘과 같다.
작게 표시되므로 외곽선은 오히려 더 중요하다.

## 5. 3D 에셋 — PNG 아님

챌린지의 **수령 발판**과 **진행 벽**은 그림이 아니라 3D 오브젝트다.
Studio(Team Create)에서 Part로 직접 만든다.

| 오브젝트 | 역할 | 유저 동작 |
|---|---|---|
| 수령 발판 | 수령 · 안전 (노랑) | 밟는다 |
| 진행 벽 (열림) | 진행 · 도박 (보라) | 통과한다 |
| 진행 벽 (미클리어 · 최종층 닫힘) | 중립 (회색) | 막힌다 |
| 클릭 파워 패드 | 힘 (주황) | 밟고 지나간다 |
| 클릭 파워 패드 (미해금) | 중립 (회색) | 밟아도 반응 없음 |

**색값은 `docs/UI.md` "3. 색" 표에서 본다.** 위 역할 이름이 그 표의 행 이름이다.

⚠️ **hex를 이 표로 옮겨 적지 말 것.** 두 곳에 적히는 순간 한쪽만 고쳐지고,
그때 어긋나는 것은 문서가 아니라 **이미 만들어진 PNG와 3D 파트**다.
화면 개수가 어긋났을 때는 문서만 고치면 됐지만 색이 어긋나면 제작물을 다시 만든다.
(2026-08-28 확인 시점에는 네 값 모두 `docs/UI.md`와 일치했다 — 어긋나기 전에 뺐다)

```
색 기준     docs/UI.md "3. 색" (버튼 btn_yellow / btn_purple과 동일)
위 글자     코드가 붙인다. 디자인은 형태와 색만
PNG 필요    없음
```

근거: `DESIGN.md` "1. 챌린지 → 선택 방식 — 둘 다 3D 오브젝트"

세 오브젝트가 월드 어디에 놓이는지(원점 · 거리 관계)는 이 문서가 아니라
`docs/UI_HANDOFF.md` "3. 배치 명세 템플릿 > 3D 파트 배치 — 아레나 좌표"에 있다.
여기는 **무엇을 어떤 크기로 만드는가**만 다룬다.

### 5-1. 수령 발판 · 진행 벽 — 최소 깊이

```
진행 방향 깊이   8 studs 이상   ← 필수 제약 (발판 · 벽 공통)
수령 발판        가로폭 · 높이 자유
진행 벽          가로폭 · 높이 고정 — 파생값 (아래)
```

수령 발판은 깊이만 하한이 있고 나머지 치수는 자유다.

⚠️ **진행 벽의 가로폭과 높이는 자유가 아니다.** 챌린지 통로 폭 전체와 아레나 경계
높이에서 파생된다(원본 `Shared/Config/ArenaConfig` `getAdvanceWallSize`, 이유는
`DESIGN.md` "1. 챌린지 > 진행 벽"). 벽에서 디자인이 정하는 것은
깊이(8 이상)와 형태 · 질감이다. 상태별 색(열림 보라 / 닫힘 회색)은 위 표와 같다.

**왜 깊이에만 하한이 있는가 — 이 값이 캐릭터 이동속도 상한을 직접 결정한다.**

발판은 밟아서, 벽은 통과해서 고르는 물건이다. 로블록스가 "밟았다"를
판정하는 방식(`Touched`)은 프레임 단위 겹침 검사라서, 캐릭터가 파트 위에
최소 3프레임은 머물러야 프레임 드랍 한 번을 흡수한다. 그 조건에서
허용 가능한 최고 속도가 나오고, 그게 게임 전체의 이동속도 상한이 된다.

```
깊이 8 (현재)  → 이동속도 상한 80
깊이 4         → 이동속도 상한 40   ← 같은 비율로 내려간다
```

상한이 내려가면 후반 유저가 힘을 아무리 키워도 더 빨라지지 않는다.
이동속도는 레벨에서 파생되는 성장 보상이라, 상한을 깎으면 성장이 안 보이게 된다.
반대로 상한을 넘기면 발판을 밟으려다 그대로 관통해서 런이 통째로 날아간다.

즉 **"깊이 좀 줄여도 되죠?"는 디자인 결정이 아니라 밸런스 결정이다.**
8 미만이 필요하면 만들기 전에 먼저 말할 것. 8 이상은 얼마든지 자유다.

(근거 → `DESIGN.md` "레벨 > MAX_WALK_SPEED는 상수가 아니다")

### 5-2. 클릭 파워 패드

```
개수    24개   (월드1 기준. 월드마다 다르다)
크기    8 x 1 x 8 studs   ← 초안. 실제 파트 바운딩 박스로 교체될 값
배치    일렬. 앞으로 갈수록 강해진다
상태    해금 / 미해금 2종
표시    BillboardGui 2줄 — 클릭 파워(위) / 해금 조건(아래). 글자는 코드가 붙인다
```

패드는 여러 개가 바닥에 깔리고 월드마다 세트가 교체된다.

**크기 8 x 1 x 8은 초안이다.** 실제 파트가 나오면 그 바운딩 박스로 교체하므로
이 숫자에 맞추려고 형태를 억지로 줄일 필요는 없다. 다만 **바꾼 값은 반드시 알릴 것** —
패드 간격과 블록까지의 거리가 이 값에서 나온다
(`docs/UI_HANDOFF.md` "3. 배치 명세 템플릿 > 3D 파트 배치 — 아레나 좌표").

**해금 여부는 색으로만 구분한다. 형태는 두 상태가 동일하다.**

⚠️ **색은 이미 배정돼 있다. 새로 고르지 않는다.**

```
해금     힘 (주황)
미해금   중립 (회색)
```

수령 발판(노랑) · 진행 벽(보라)과 **반드시 구분돼야 한다.** 그 두 색은
"둘 중 하나를 고른다"는 뜻으로 이미 묶여 있어서, 패드에 쓰면 유저가 패드도
선택지로 착각한다. 패드는 고르는 대상이 아니라 밟고 지나가며 성장시키는 것이다.
배정 근거와 색값은 `docs/UI.md` "3. 색 > 3D 오브젝트 색 배정".

## 9. 새 화면 · 키트 그림 (지시서 #39, 2026-11-26 — 1월 UI 템플릿용)

> 1월에 "UI 템플릿"이 만드는 그림의 규격이다. 넣는 곳은 코드 한 파일(`Shared/Config/UiSkin.lua`의 `images`)이고,
> 넣기 전까지는 지금 모양(색 도형)이 그대로 보인다. 부품 · 함수 · 스킨 구조 원본은 `docs/UI.md` "UI 키트".
> 크기 px는 **1920 × 1080 화면 기준 실제 표시 크기**(코드의 Scale 값에서 환산 — 창 크기가 바뀌면 같이 바뀐다).
> 그림은 표시 크기보다 크게 그리고 9-slice로 늘린다. 모서리 여백은 "1. 9-slice" 규칙 그대로 **24px**.
> **[템플릿]** = 1월 템플릿이 만드는 것 · **[ASSET_ORDER]** = 새 경제 에셋 주문서(`docs/ASSET_ORDER.md`)에 이미 있는 것.
